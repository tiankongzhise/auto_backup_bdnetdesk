# pywebview UI 设计文档

## 1. 目标与依据

本轮 UI 重构挂靠 P3 阶段 14 打包发布与最终验收，目标是把当前 PySide6 桌面界面替换为 pywebview 承载的原生静态 Web UI，同时保留既有备份、授权、校对、清理、恢复和云同步业务能力。

设计目标：

- 面向普通 Windows 用户，把主流程从“页面堆叠”改为“工作台驱动”。
- 降低内部 ID、路径、同步实体等工程细节在 UI 中的存在感。
- 保持桌面工具的密度和可扫描性，不做营销式首页、夸张 hero 或装饰性视觉。
- 所有写入类动作都经过后端 bridge 串行化，避免并发 UI 操作破坏 SQLite、云端同步、百度上传或恢复状态。
- UI 只显示脱敏 DTO，不显示 Device Token、百度 token、用户密码、wrapping key、本地完整敏感路径或完整远端路径。

官方依据：

- pywebview Usage 文档说明可通过 `webview.create_window(...)` 创建窗口并用 `webview.start()` 启动，也支持加载本地 `index.html`，相对本地路径会由内置 HTTP server 承载；`file://` 方式不推荐用于分发。
- pywebview Javascript-Python bridge 文档说明 `js_api` 暴露的 Python 方法在 JS 中通过 `window.pywebview.api.*` 调用，返回 Promise；暴露函数在独立线程中执行且不是线程安全的，因此本项目必须在 Python bridge 内做写操作串行化。
- pywebview Freezing 文档说明 Windows/Linux 可用 PyInstaller，并通过 `--add-data` 打包 `index.html` 或前端构建目录；本项目沿用现有 PyInstaller onedir 发布方式，把静态 UI 目录作为 data 加入 bundle。
- pywebview Installation 文档说明 Windows 最新 Chromium 路线依赖 Microsoft WebView2 Runtime；干净 Windows 验收矩阵需要覆盖 WebView2 缺失时的提示或安装策略。

## 2. 信息架构

新 UI 使用左侧主导航 + 顶部状态栏 + 右侧主工作区，不再把每个底层能力平铺为等权页面。

主导航：

- 工作台：默认首页，展示系统状态、下一步动作、最近任务、风险提醒和正在运行的长操作。
- 备份：创建任务、添加来源、设置缓存、输入一次性密码、开始/继续/暂停/取消任务。
- 百度授权：账号列表、设备级授权状态、新增授权、选择当前账号、token 解密自检。
- 恢复：按任务和来源浏览恢复候选，选择本地或远端 archive，执行来源级恢复。
- 清理：列出可清理原始来源，默认回收站，高级永久删除隐藏并强确认。
- 校对与同步：包含来源映射、远端校对、本地 outbox 状态和 Cloud Sync summary 回读。
- 设置：缓存目录、上传参数、备份根目录、发布候选诊断信息和 WebView2/版本信息。

工作台首屏：

- 顶部摘要：当前设备摘要、当前百度账号、最近备份状态、待处理风险数。
- 下一步动作：未授权时显示“完成百度授权”；无任务时显示“添加来源并创建备份”；有失败可重试任务时显示“继续任务”；有可恢复记录时显示“做一次恢复演练”。
- 最近任务表：任务名、状态、来源数、最后阶段、更新时间、同步状态、可执行动作。
- 风险提醒：缓存不足、云端历史拉取失败、远端校对差异、清理前未演练恢复、WebView2 运行时异常。

## 3. 视觉原则

整体风格：

- 安静、专业、密集但不拥挤，优先帮助用户判断“现在能不能备份、下一步做什么、哪里有风险”。
- 使用中性浅色底、低饱和强调色和清楚的状态色；避免单一蓝紫渐变、卡片堆叠、装饰光斑和大面积插画。
- 卡片只用于独立信息块、重复条目和确认面板；页面主体使用全宽分区和表格布局。
- 按钮使用明确命令：主要按钮只保留当前上下文最重要动作；危险按钮必须降权并二次确认。
- 表格默认紧凑，长文本截断显示摘要，hover 或展开区显示更多脱敏说明；不把完整路径铺满界面。

状态语言：

- 任务状态使用用户可理解文案：待开始、运行中、等待重试、已暂停、已完成、已取消。
- 同步状态区分本地已落盘、云端待同步、云端已同步、云端回读失败。
- 远端校对差异必须说明对比口径：本地 SQLite 上传账本 vs 百度 `list/listall` 实际对象。
- 错误消息只显示阶段、原因和下一步，不显示 token、密码、完整本地路径、完整远端路径或 stdout/stderr 原文。

## 4. 关键流程

### 4.1 首次授权

1. 工作台发现未选择百度账号，显示“完成百度授权”。
2. 用户进入百度授权页，点击“新增授权”。
3. UI 展示百度官方授权 URL、用户码和二维码；账号密码只在百度官方页面输入。
4. 用户完成授权后输入本项目授权密码，后端完成密文 token 入库。
5. 账号列表刷新，用户选择当前设备对应账号。
6. 工作台下一步动作切换为创建备份。

### 4.2 新建备份

1. 用户进入备份页，通过单一“添加来源”入口或拖拽加入文件/文件夹。
2. bridge 调用原生文件/目录选择能力；后端根据路径自动识别 `file` 或 `directory`。
3. 用户填写任务名、缓存目录和运行参数。
4. 用户点击“开始备份”，弹出一次性密码面板，输入归档密码和授权密码。
5. bridge 创建长操作并立即清空前端密码字段；前端通过 `operation_id` 轮询。
6. 任务阶段依次展示扫描、去重、归档、上传、同步、远端校对和完成。

### 4.3 继续任务

1. 工作台和备份页都能看到 `running`、`paused`、`failed_retryable` 任务。
2. “开始”只对 `queued` 生效，“继续”只对可恢复运行状态生效。
3. 继续时仍需输入一次性归档密码和授权密码。
4. 若云端历史导入得到运行中任务但本机没有后台 worker，UI 仍允许继续执行既有 pipeline。

### 4.4 恢复演练

1. 恢复页刷新前先通过设备历史 helper 拉取本机云端历史。
2. 候选按“备份时选择的来源”聚合，一行代表一个文件来源或文件夹来源。
3. 用户选择手动恢复目录，默认冲突策略为保留两者。
4. 本地 archive 存在时直接解密恢复；本地缺失但远端确认存在时，输入授权密码后通过百度 dlink 下载，再校验恢复。
5. 恢复后重新计算 SHA256，只有校验通过才标记成功。

### 4.5 原始数据清理

1. 清理页只显示已完成、已验证、远端对象已确认且源文件未变化的候选。
2. 默认方式为移入 Windows 回收站；隔离目录作为回收站失败时的备选。
3. 永久删除放入高级区，默认隐藏，必须填写精确确认短语。
4. 清理前提示用户先做恢复演练；清理动作写入本地记录和 outbox。

### 4.6 远端校对

1. 校对与同步页默认展示最近任务的来源映射和同步状态。
2. 远端校对需要用户选择 scope：任务、上传会话或远端目录。
3. 执行前需要当前百度账号和授权密码以解密 token。
4. 差异报告区清楚标注 SQLite/Baidu 对比口径，修复动作必须显式确认。

## 5. 安全与交互约束

- 前端不得持久化密码；密码字段提交后立即清空。
- 前端不得把 bridge 返回结果写入 localStorage/sessionStorage。
- 所有 bridge 返回 DTO 默认脱敏；需要定位时显示 hash、短 ID、文件名或任务名。
- 所有写操作在 Python bridge 内进入同一把写锁；长任务由 operation registry 管理。
- 前端只轮询 `get_operation(operation_id)`，不得重复触发同一写动作。
- 关闭窗口时若有运行中的备份、恢复、校对或清理操作，必须提示用户仍有任务运行。

## 6. 后续交付边界

本设计文档只定义 pywebview UI 的产品与交互方向。下一步必须新增 `client/docs/frontend_spec_pywebview.md`，把静态文件结构、bridge DTO、页面状态、错误处理和测试方式落实为可实现规格。实现阶段不得改变百度上传协议、云端 API 契约、SQLite schema 或备份/恢复核心业务语义。
